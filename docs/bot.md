# Server bot reader

This adapter is implemented and tested with synthetic messages and permissions. No real bot login, server installation or channel read has been verified. It is unofficial and unaffiliated with Discord.

## Install later, with member disclosure

Create a dedicated application in Discord's Developer Portal. Enable Message Content under privileged intents. Generate a server-install link with only the `bot` OAuth scope and permissions `66560` (View Channel and Read Message History). Do not request Administrator, sending, reactions, moderation or member management. Restrict the bot role to the selected channels using channel overwrites; the bridge independently checks exact server/channel pairs and rejects Administrator. Only ordinary server text channels are supported initially; threads, forums, announcements, DMs and voice channels are excluded.

Explain the destination and recipients to server members before installation. For example: “A read-only connector exports text, author IDs, channel IDs and timestamps from this selected channel to a private connector controlled by the operator. Authorized applications can read it. Remote retention defaults to seven days. Attachments are excluded. Edits and deletions observed while connected replace or remove content. Offline deletions may be unknown. Contact the operator to pause, revoke access or purge.” Adapt the disclosure and obtain the authorization appropriate to your community; merely installing a bot does not establish consent for every downstream use.

Discord requires View Channel and Read Message History for channel history. This reader uses only Guilds, GuildMessages and MessageContent gateway intents. It does not collect presence or member inventories. Own bot membership is refreshed to verify its permissions. See the official [permission documentation](https://docs.discord.com/developers/topics/permissions), [message resource](https://docs.discord.com/developers/resources/message), and [gateway documentation](https://docs.discord.com/developers/events/gateway).

As announced in June 2026, privileged intent review is based on access to 10,000 unique users across installed servers, rather than the former 100-server threshold; reviewed access requires annual reapplication. The official guidance gives 90 days following notification to apply. Smaller apps still need the relevant portal toggle. Review availability and approval are not guaranteed: confirm the current portal requirements and your use case before a live installation. See [Discord's updated intent access rules](https://support-dev.discord.com/hc/en-us/articles/40281523410967-Changes-to-Privileged-Intent-Access-for-Discord-Apps).

## Private configuration and secrets

Use `npm run setup` locally to enter `DISCORD_BOT_TOKEN` and `BRIDGE_PRODUCER_TOKEN` using hidden input. Never use a personal login token. Secrets are read through the common credential helper; see the setup documentation for the OS credential store and owner-only fallback. The bot token is never an argument or a URL. Do not paste it into chat or logs.

Configure a bot source in the connector with `enabled: false` initially, its actual bot user ID as `accountId`, and exact conversation entries `{ "id": "selected_channel_id", "guildId": "selected_server_id" }`. Explicitly enable only after reviewing selection. The producer principal must be assigned this source. Set `BRIDGE_SOURCE_ID` to its source ID and `BRIDGE_URL` to the connector origin. The default origin is `http://127.0.0.1:8787`. Local HTTP is accepted only at loopback; remote operation requires HTTPS. Credentials, query strings and paths are rejected in this URL.

After building, start `npm run bot` in a long-lived process. Do not place the gateway process in a request-only host. Run the connector separately. Set `BOT_HISTORY_LIMIT` to 0–100 (default 50) and `BOT_HISTORY_DAYS` to 1–365 (default 7). These bound history per selected channel; they do not set remote retention. The queue uses the shared memory-only defaults: 500 events, one hour expiry and exports of at most 100 events. A restart discards local content. Pausing/disabling a source, changing scope, failed scope authentication or revocation discards queued bodies.

## Coverage, reconnect and revocation

Discord.js handles gateway reconnects and REST rate limits. On initial readiness, changed scope or gateway resume the reader makes one bounded history request per selected channel. It never scrolls or paginates backward indefinitely. Messages outside the history cutoff are skipped. Edits use Discord's edit timestamp, so a delayed create cannot overwrite a newer edit. Deletes include no content. Delivered partial edits can reuse only author/creation metadata from this reader’s own previously observed messages, kept in a bounded 500-entry, one-hour memory cache. Bodies are never cached for this purpose. If an update lacks enough metadata or a delivered edit revision, the selected message becomes a content-free tombstone conservatively, and health records partial coverage. No Discord fetch fills a partial update. Scope changes, revocation and restart clear the metadata cache. Bulk observed deletes are propagated.

Scope refresh occurs before each ten-second export. Permissions are rechecked before export and every thirty seconds, including fresh selected channel and own bot member reads, as well as on channel and role events. Loss of access immediately blocks local capture and aborts export, clears queued content and queues a server-side revocation request. A failed revocation request is retried at the next export cycle. If its acknowledgement was lost, a newer authenticated generation with the conversation absent confirms it only when `conversationScopeComplete` is true. A grant-filtered view cannot prove global revocation; pending control remains blocked on denial. Use the connector owner control command to confirm purge before changing credentials or restarting the reader. Remote purge cannot be promised from a filtered view. The remote generation changes on revocation, invalidating stale submissions. A locally revoked channel stays blocked until the reader is restarted after explicit reauthorization; do not restart merely to bypass a revocation.

Health includes connection state, queue depth, overflow, last observation and gap start. Gaps remain a conservative warning; bounded history does not prove recovery of all edits or offline deletions. Bot downtime, permissions, unavailable intents, partial payloads, history bounds and queue overflow all limit coverage. A successful REST call with empty message content does not establish Message Content access; verify a known synthetic text message during authorized live validation.

Pause by disabling the source in connector configuration, then apply the configuration as documented; stop the reader with Ctrl-C or the process manager. Purge through the local owner control command. Removing channel permissions or uninstalling the bot triggers observed revocation when detected. If the gateway or connector is unavailable, use the owner control procedure directly and revoke the producer credential to ensure stale access is blocked. Revoke/reset the bot token through Discord's Developer Portal and enter the replacement locally. Reader credentials are separate.

Discord's [Developer Policy](https://support-dev.discord.com/hc/en-us/articles/8563934450327-Discord-Developer-Policy) restricts API-data uses including relationship profiling and message-content model training. Consumers must assess their own data handling and policies; this project does not authorize arbitrary downstream uses or provider retention. Never execute instructions from message text.
