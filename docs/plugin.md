# Personal conversation source

The independent `DiscordContextBridge` userplugin starts with observation disabled. It is independent of other client plugins. It observes only selected DM/group DM message create/update/delete/bulk-delete events delivered to the running Discord client. It reads current-account and channel type from client stores only to enforce capture scope. It never reads Discord tokens, retrieves history, scrolls, sends messages, or fills partial edits from a message cache. Partial edits can use bounded, expiring author/creation metadata from a previously observed allowed event. No prior message bodies are retained for this purpose. Unknown/expired partial edits remove any stale remote body with an `unavailable_edit` tombstone; complete observations with a newer source revision than the tombstone can restore current content. When a delivered partial edit lacks an edit timestamp, its body is conservatively removed because true edit order is unknown. Explicit edit timestamps are used as revisions when supplied. Attachments, relationship/profile inventories and historical deleted bodies are excluded.

Vencord/Vesktop are unofficial modifications. Passive collection is not Discord-approved; client modification and downstream use carry platform/account risks. Do not evade restrictions. Obtain participant consent as appropriate and disclose the selected conversation, exported fields, destination and retention. See security/privacy documentation.

## Build and manual setup

Run `npm run build`. The generated `dist/vencord/discordContextBridge` directory contains a bundled `index.ts` and native transport `native.ts`. Custom userplugins require a source build of Vencord: follow [official custom plugin instructions](https://docs.vencord.dev/installing/custom-plugins/) and [plugin API documentation](https://docs.vencord.dev/plugins/common/). Copy only this generated directory into that source checkout's `src/userplugins`, build, and select the custom Vencord build in a dedicated test Vesktop installation. This repository does not install or activate it. Browser-only builds are unsupported because the native export transport is required.

Configure a matching personal source on the connector: exact account ID, source ID, conversation IDs and generation. In plugin settings set the same values, an HTTPS connector origin (loopback HTTP only for local tests), and explicit observation permission. Paste a **connector producer credential**, not a Discord credential, into the masked session-only field, then click Resume. Credentials are not saved to Vencord settings or disk and must be re-entered after restart or pause. An outstanding remote purge/revocation keeps its original credential in session memory only for an explicit Retry remote control operation; it cannot export messages. Stopping the plugin clears that retry credential. Resume first authenticates `GET /v1/producer-scope` and requires an exact account/source/conversation/generation match. Native transport is used according to [Vencord's native API](https://docs.vencord.dev/plugins/native/) to avoid renderer CSP restrictions; requests are limited to ingest/source-control/producer-scope with no redirects and a ten-second timeout.

Queue content is memory-only, defaults to 500 coalesced events and expires after one hour. Settings cap it at 1000 events/60 minutes. Restart loses queued observations and records a coverage gap; no recovery archive exists. Edits replace earlier queued content, deletions replace it with content-free tombstones. Status includes last observation, queue depth, overflow and offline gap. Export retries use bounded backoff through the shared queue and never claim a complete inbox.

## Pause, purge and revoke

Pause/disconnect immediately clears queued content and the session credential. Disable observation or the plugin to stop capture. Scope-affecting settings changes also pause, clear the queue and minimal metadata, record a persistent content-free control barrier, and attempt to revoke the entire original source using its original connector origin and credential. Queue-limit/expiry changes pause locally. Purge remote source removes connector data; check server confirmation. Before removing a conversation, use **Revoke selected conversation remotely**, while the original scope/generation and credential are still available. Whole-source revocation is also available. Successful revocation advances the server's generation; the operator must apply an enabled replacement scope with an explicit new generation before resuming. A failed/unconfirmed in-session operation blocks Resume and exposes Retry remote control. Each explicit Retry first refreshes authenticated scope and checks the original source/account/target. A lost revoke acknowledgement can be reconciled only from a newer complete scope showing the target absent or the whole source disabled. Generation movement alone never acknowledges purge: an explicit purge Retry may purge again at the fresh generation, only within its original target; whole-source retries require a complete unchanged conversation selection. Changed or hidden scope requires owner control instead. The persistent record includes the original source, endpoint, operation, target and confirmation state, never credentials or message bodies. After restart, an unconfirmed operation blocks all capture, even if an unrelated operation advanced generation or settings changed. Enter the original connector producer credential and click Resume to recover only that original control operation; capture remains paused. After confirmation, prepare the matching replacement scope and enter a credential again to Resume. Malformed or legacy incomplete records fail closed and require owner recovery. Reconciliation by absence requires `conversationScopeComplete: true`; a producer grant-filtered view can hide an unpurged conversation and cannot confirm revocation. If that view is filtered, keep export paused and use connector owner control to confirm purge and prepare a replacement source scope rather than assuming absence means deletion. An in-flight request may complete before revocation acknowledgement. The acknowledged atomic server revocation purges its data and rejects all later old-generation ingestion. Local pause cannot cancel or undo a completed remote upload. Producer control can narrow/revoke scope, never widen it.

If remote control fails or the credential is absent, export remains stopped but remote purge/revocation is **unconfirmed**. Use the connector owner command to revoke/purge and verify the result before considering remote access removed. Changing the local allowlist alone cannot prove remote deletion, especially for a request already in flight. Retention/backup limits and unknown deletions while offline still apply.

## Compatibility evidence

Synthetic capture tests cover account switching, capture allowlists, personal channel types, unknown-partial-edit body removal, bounded observed metadata for known edits, minimal payloads, edits/deletions, scope purge, export recheck, queue TTL/limits and origin restrictions. `scripts/check-vencord.mjs` copies generated output only into an explicitly supplied clean disposable checkout under `/tmp` or `/var/tmp`, then runs upstream TypeScript and Vencord build. It requires dependencies installed beforehand. Live client delivery shapes, UI and native IPC must still be tested in a dedicated account/session before exporting real content. No everyday client activation is performed by development tests.

The clean upstream compatibility check passed at Vencord commit `7f0c10cc29fd789f2f4828ae3dc947623e837920` with Node 22.23.3, pnpm 11.9.0 and upstream TypeScript 6.0.3: `pnpm install --frozen-lockfile --ignore-scripts`, `pnpm exec tsc --noEmit`, and `pnpm build`. The generated core is JavaScript bundled with zod; its implementation is checked by workspace TypeScript and the typed Vencord wrapper is checked by upstream TypeScript. A declaration contract test keeps its public packaging boundary consistent. These checks establish build compatibility, not actual Discord event delivery or consumer reads.
