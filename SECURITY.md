# Security reporting

This initial release has synthetic validation and requires authorized live validation before use with real conversations. No guarantee of complete message or deletion coverage is made.

Use GitHub's private vulnerability reporting for this repository if available. If private reporting is unavailable, open an issue containing only a request for a private reporting channel and a broad affected component; do not include exploit details, credentials, message bodies, account IDs or private deployment information. Do not send sensitive material until a private channel is established. No response-time commitment is currently made.

Include affected version/commit, reproducible synthetic steps, expected/actual authorization behavior and a sanitized impact description. Do not probe real communities, consumer accounts or third-party infrastructure without their authorization.

Read [security/privacy boundaries](docs/security.md) and [pause/revocation procedures](docs/setup.md). Rotate exposed credentials through their issuer and purge affected scoped data; deleting a public issue or repository file does not revoke a credential or erase Git history/backups.
